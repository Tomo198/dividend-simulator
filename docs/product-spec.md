# 分配金・配当シミュレーター 詳細設計書

- 文書版: 1.6
- 作成日: 2026-07-15
- 想定プロダクト: 既存の積立・取り崩しシミュレーター、LIFECompassとは別の独立Webアプリ
- 想定対象: ETF、個別株、REIT（公開MVPの入力・表示は円換算値に統一）
- 初期データ方針: 手動入力を基本とし、計算エンジンを外部データ取得から分離する

## 0. 結論

このアプリの中核価値は、現在利回りの高低ではなく、同じ投資条件で次の問いに答えることにある。

1. この銘柄に投資すると、税引後で年・月いくら受け取れるか
2. 目標配当を得るには、いくら必要か、毎月いくら積み立てればいつ到達するか
3. 配当と価格の継続的な変化、税金、再投資、コストを含めると将来どうなるか
4. ETF A・B・Cは、初期収入、将来収入、総資産、コスト、元本維持のどこで優位か

公開MVPには「単一銘柄」「目標逆算」「1〜3銘柄の確認・比較」をすべて含める。ただし、過去データ自動取得、モンテカルロ、ポートフォリオ、配当安全性評価は含めない。

比較結果は総合1位を断定しない。「初期の手取り配当が最大」「10年後の総資産が最大」「目標到達が最速」「経費率が最小」のように、利用者の目的ごとの判断材料を表示する。

## 1. プロダクト定義

### 1.1 仮称

正式名称候補: **分配金・配当シミュレーター**

補助コピー:

> ETFや高配当株の受取収入と資産の将来を、税金・コスト込みで比較試算する

### 1.2 対象ユーザー

- ETF・高配当株の購入前に、受取額を知りたい人
- 月1万円、3万円、5万円などの配当目標を持つ人
- 高利回りETFと増配ETF・増配株を比較したい人
- 米国ETFなども、円換算した価格・配当と外国源泉税率で概算したい人
- 分配金だけでなく、総資産や元本維持も確認したい人

### 1.3 解決する課題

- 表示利回りだけでは、税引後の受取額が分からない
- 高分配商品と増配商品の長期差を比較しづらい
- 経費率と税金を別々に計算する必要がある
- 月平均額と実際の支払頻度が混同されやすい
- 多額の分配金を受け取っていても、評価額が減っている場合がある
- 毎月の積立額と目標達成時期の関係が分かりにくい

### 1.4 非目標

MVPでは次を行わない。

- 特定銘柄の売買推奨
- 将来リターンの保証
- 「最も良いETF」の断定
- 確定申告や外国税額控除の完全再現
- 分配原資が利益か元本払戻しかの自動判定
- リアルタイム株価・配当履歴の自動取得
- 証券口座連携

## 2. 成功条件

### 2.1 ユーザー価値の成功条件

- 3分以内に、単一銘柄の10年後の手取り配当と総資産を確認できる
- 1銘柄を詳しく確認でき、同じ100万円・毎月5万円などの共通条件で最大3銘柄を比較できる
- 目標月額と積立額から、必要投資額と初回達成時期が分かる
- 高分配型と、現在利回りは低くても増配する型の違いが結果に表れる
- 経費率を実績リターンから二重控除しない

### 2.2 技術的な成功条件

- 計算ロジックがUIから分離された純粋関数である
- 月次計算の同一入力は常に同一結果になる
- すべての主要式に単体テストがある
- 確認・比較は単一銘柄エンジンを入力件数分だけ呼び、別計算を持たない
- 計算中は丸めず、表示時のみ通貨単位へ丸める
- 保存データにスキーマバージョンを持たせる

## 3. 設計原則

### 3.1 事実値と仮定値を分ける

画面上で、次を視覚的に分離する。

- 現在・実績: 現在価格、過去12か月分配金、実績利回り、経費率
- 将来仮定: 年間配当変化率。価格の値動きは0%へ固定
- 制度・利用者条件: 税率、NISA

自動取得を追加した後も、取得値を将来仮定へ無条件にコピーしない。

### 3.2 分配収入と資産価値を必ず併記する

年間配当だけを大きく表示しない。最低でも次を同じ結果面に置く。

- 年間税引後配当
- 月平均税引後配当
- 累計現金受取額
- 期末評価額
- 受取額込み総資産
- 累計投資額との差

### 3.3 経費率を二重控除しない

経費率はETF・投資信託の信託報酬や運用管理費用を想定する。個別株では通常0%とする。ETFの運用経費はファンド資産から支払われ、投資リターンを低下させる。したがって、実績価格や実績分配金には通常すでに影響が含まれている。SECの投資家向け説明でも、ETFの運用経費はファンド資産から間接的に支払われ、リターンを低下させると説明されている。

公開画面では価格成長率を入力させず、値動きを0%へ固定したうえで経費率を控除する。次の入力基準は計算エンジンの回帰互換として残す。

- `netOfExpense`: 経費率控除後の価格成長率。経費率を再控除しない。
- `grossBeforeExpense`: 経費率控除前の価格成長率。公開画面は0%を渡し、シミュレーターが経費率を控除する。

参考: [Investor.gov: Mutual Fund and ETF Fees and Expenses](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/mutual-fund-and-etf-fees-and-expenses-investor-bulletin)

### 3.4 税金は概算プリセット＋上書き

日本の上場株式等の配当は、一般的な個人の課税口座では所得税等15.315%と地方税5%の源泉徴収が基本となる。一方、NISAの対象となる運用益・配当・分配金は国内では非課税になる。実際には商品、受取方法、居住地、申告、外国税額控除などで異なるため、固定値ではなくプリセットとして扱う。

- 課税口座・外国税額控除を考慮: 外国源泉税の100%を回収できた場合の上限概算
- 課税口座・外国税額控除なし: 外国源泉税と国内税を控除
- NISA口座: 国内税率0%。外国源泉税は設定値を残し、外国税額控除は適用しない
- 手動設定: 外国源泉税率、国内税率、国内課税ベース、外国税回収見込率を上書き

外国税額控除は所得や申告状況などで実際の控除額が変わる。「控除を考慮」は満額回収できた場合の上限ケースとして表示し、控除時期は再現せず受取額へ同時反映する。

参考:

- [国税庁: 配当金を受け取ったとき](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1330.htm)
- [金融庁: NISAを知る](https://www.fsa.go.jp/policy/nisa2/know/index.html)
- [日本証券業協会: NISAのよくある質問](https://www.jsda.or.jp/nisa/faq/)

### 3.5 「元本毀損」を断定しない

利回り、価格、分配額だけでは、分配原資が利益か元本払戻しかを確定できない。MVPでは「元本払戻し」と表示せず、次の観測値に分解する。

- 元本維持率 = 期末評価額 ÷ 累計投資額
- 1口価値維持率 = 期末価格 ÷ 初期価格
- 総資産差額 = 期末評価額 + 現金残高 + 累計現金受取額 - 累計投資額
- 評価額が累計投資額を下回った期間

表示文例:

> この試算では評価額が累計投資額を下回ります。分配金の原資が元本払戻しであることを示すものではありません。

## 4. 機能範囲

### 4.1 公開MVP

#### A. 単一銘柄シミュレーション

- 商品種別を選ばず、ETF、個別株、REITを共通モデルで入力
- 初期投資、毎月積立、運用期間
- 現在価格、年間1口配当、または利回り入力
- 年間配当変化率（負数で継続的な減配を表現）
- 将来の値動きは0%に固定し、経費率だけを価格へ反映
- 再投資率0〜100%
- 年間配当を基準に、月平均へ換算して概算
- 入力・表示通貨はJPYに固定
- 外国資産は、利用者が円換算した現在価格と年間配当を入力
- 外国税、国内税、NISA
- 経費率
- 公開MVPは売買手数料0、端数口数あり、期末売却なしの概算に固定
- 将来推移と主要KPI
- 現在受取額、将来推移、年額・月平均、コスト・税、感応度の単体向け機能
- 固定4ケースの感応度分析

#### B. 目標配当からの逆算

- 月額または年額目標
- 税引前または税引後目標
- 現在投資額
- 毎月積立額
- 必要投資額
- 不足額
- 目標到達時期
- 指定期限までに目標へ届くための必要毎月積立額
- 積立額3パターンの比較

#### C. 1〜3銘柄の確認・比較

- 1銘柄だけでも入力・試算でき、比較向けの順位表示は行わない
- 共通投資条件での公平比較を既定にする
- 各銘柄固有の利回り、配当変化率、経費率、税を設定
- 共通条件と個別条件を明確に分離
- 比較表、配当推移、総資産推移
- 条件別ハイライト
- 同じ投資額 / 同じ目標配当の2比較モード
- 固定ストレスに対する結果の安定性

#### D. 保存

- ブラウザ内に現在の作業内容を保存
- フェーズ5Aでは複数の試算を名前付きで保存し、一覧から復元・削除できる
- フェーズ5Bでは名前付き保存一覧をJSONファイルへ書き出し・読み込みできる
- スキーマバージョン付き
- 単一・目標・比較の入力と選択中モードを保存し、再読み込み時に復元
- 外部アカウント、クラウド同期、URL共有は対象外

### 4.2 MVP後の優先機能

#### フェーズ5: 使いやすさと共有

- 複数試算の名前付き保存
- JSON入出力
- 3シナリオ同時表示
- 印刷・PDF向けレイアウト

#### フェーズ6: プリセット

- 人気ETF・株の手動管理プリセット
- データ更新日、出典、実績値と仮定値の区別
- プリセット値の編集

#### フェーズ7: 自動取得

- ティッカー検索
- 現在価格、過去12か月分配金、分配履歴
- キャッシュ、取得日時、欠損時の手入力フォールバック

#### 将来候補

- 過去実績バックテスト
- モンテカルロ
- インフレ調整後の実質配当
- ポートフォリオ全体の月別入金カレンダー
- 最大ドローダウン、ボラティリティ
- 配当性向・分配原資・ROC情報
- 証券口座連携

## 5. 情報設計・画面構成

### 5.1 グローバル構成

```text
トップ
├─ 今いくら受け取れる？
├─ 積立・将来シミュレーション
├─ 目標から逆算
├─ 年額・月平均
├─ コスト・税の影響
├─ ストレス試算
├─ 1〜3銘柄を確認・比較
└─ 保存した試算
```

トップ階層は目的別の機能選択とし、各機能が同じ「銘柄設定」と「投資条件」を参照する。利用者は一度入力した銘柄を別機能でもそのまま使える。デスクトップでは機能メニュー、モバイルでは目的選択を使う。各機能では入力と結果を一画面に置き、入力変更で即時再計算する。

### 5.2 トップ

目的別カードを7つ置く。最初の4つを主要カード、残り3つを「さらに分析する」として配置する。

1. 今いくら受け取れる？
2. 積み立てると将来どうなる？
3. 月○万円にはいくら必要？
4. 1〜3銘柄を確認・比較する
5. 月ごとの入金を確認する
6. 税金・コストの影響を見る
7. 配当の変化を試す

トップでは金融用語の説明を増やさず、サンプルを1つだけ提示する。

### 5.3 単一銘柄ワークスペース

単体分析を一枚の巨大なダッシュボードにはしない。銘柄設定を共有する複数の機能として構成する。

```text
選択中の銘柄: 銘柄A
基本設定を編集 | 銘柄を保存

利用できる機能
├─ 現在の受取額
├─ 積立・将来推移
├─ 目標逆算
├─ 年額・月平均
├─ コスト・税の影響
└─ ストレス試算
```

比較は別ワークスペースだが、比較表の各列から「この銘柄を単体で試算」を選ぶと、入力を保持したまま単体機能へ移動できる。

#### 入力領域

1. 銘柄情報
2. 投資条件
3. 将来仮定
4. 口座・税
5. 税・経費の詳細設定

現在値、投資条件、将来仮定、制度条件を一つのグループへ混在させない。単一銘柄画面では入力欄から結果へ、結果見出しからグラフと年次表へ直接移動できる導線を置く。結果は主要KPIの直後にグラフを表示し、補助指標と年次表を続ける。

#### 結果上部のKPI

- 初年度の税引後配当
- 10年後または選択年の税引後配当
- 月平均手取り
- 期末評価額
- 受取額込み総資産
- 目標達成時期（目標設定時）

#### グラフ

1. 年間税引後配当の推移
2. 評価額・累計投資額・総資産の推移
3. 累計現金受取額と累計再投資額

各グラフはX軸・Y軸に中間目盛りと補助線を表示する。グラフ内の任意の年をタップまたはクリックすると、その年の全系列の値をグラフ直下へ表示する。キーボードでは左右キー、Home、Endで選択年を移動できる。

PCでは横長の描画領域と詳細な目盛りを使う。画面幅640px以下のスマートフォンでは、同じ計算データから縦を高くした専用の描画比率、少ない目盛り、大きな軸文字とタップ判定へ切り替える。別画面の拡大表示は設けず、グラフ上でもブラウザ標準のピンチズームを妨げない。

#### 詳細表

年ごとに次を表示する。

- 年
- 累計投資額
- 保有口数
- 1口価格
- 1口年間配当
- 予想利回り（1口年間配当÷1口価格）
- 税引前配当
- 税引後配当
- 現金受取
- 再投資額
- 評価額
- 総資産

#### 単体向け機能

1. **現在の受取額**
   - 投資額または口数から、税引前・税引後の年額と月平均を計算
   - 概算口数と投資額を表示
2. **積立・将来推移**
   - 初年度、5年後、10年後、期末の税引後配当
   - 1口配当、保有口数、評価額、総資産、再投資効果
   - Yield on Cost、累計手取り受取率
3. **年額・月平均**
   - 税引前・税引後の年額
   - 月平均は年額÷12で表示
   - 実際の入金月ではないことを明記
4. **コスト・税の影響**
   - 外国税、国内税の累計
   - 経費率と入力基準
   - 税・コストなしの反実仮想との差
   - 経費控除前モードのみ、経費率ゼロとの差を「推定経費影響」として表示
5. **ストレス試算**
   - 使用した全仮定の一覧
   - 配当成長率、価格成長率を小幅に変えた感応度
   - 配当と価格が同時に弱くなるストレス結果

「目標逆算」は独立機能だが、選択中の銘柄設定をそのまま利用する。

積立・将来推移にある「増配と再投資がそれぞれ何を増やしたか」は、同じ入力から次の反実仮想を再計算し、期末値の差を参考表示する。

- 元のケース
- 配当変化率だけ0%にしたケース
- 再投資率だけ0%にしたケース

差分は厳密な要因分解ではなく、他の条件を固定した参考比較であると明記する。

#### 感応度分析

MVPでは過剰な自由度を持たせず、次の固定ストレスだけを用意する。

| ケース | 配当変化 | 価格変化 |
|---|---:|---:|
| 入力どおり | 入力値 | 入力値 |
| 配当弱気 | 入力値-3pt | 入力値 |
| 価格弱気 | 入力値 | 入力値-3pt |
| 複合ストレス | 入力値-3pt | 入力値-3pt |

表示する結果は期末税引後配当、期末総資産、目標到達時期の3つに絞る。感応度を変えた値が-100%以下にならないよう下限を設ける。

### 5.4 目標逆算画面

#### 入力

- 目標額
- 月額 / 年額
- 税引前 / 税引後
- 現在投資額
- 毎月積立額
- 達成希望時期（任意）
- 対象銘柄の仮定一式

#### 結果

- 現時点の必要投資額
- 現在との差額
- 現在価格での必要口数
- 積立を含む初回達成年月
- 指定期限がある場合の必要毎月積立額
- 達成時の累計投資額
- 達成時の評価額
- 目標未達の場合は「期間内に未達」と表示

積立額比較は、既定で現在設定の0.6倍、1.0倍、1.5倍を候補にし、編集可能にする。0円設定の場合は1万円、3万円、5万円を表示する。

### 5.5 比較画面

入力件数は1〜3件とする。1件だけの場合は比較ではなく、その銘柄の収入・資産・目標を詳しく確認する表示に切り替え、条件別ハイライト、差分説明、比較安定性の回数表示は出さない。「この銘柄を単体で詳しく試算」から入力を保持したまま単一銘柄ワークスペースへ移動できる。2件以上の場合は比較表示を行う。

#### 入力構造

```text
共通条件
├─ 初期投資額
├─ 毎月積立額
├─ 運用期間
└─ 目標配当

銘柄A / B / C 個別条件
├─ 価格、配当、利回り
├─ 配当変化
├─ 価格変化
├─ 経費率
└─ 税金
```

#### 比較モード

目的の違いを混ぜないよう、上部で比較方法を選ぶ。

1. **同じ投資額で比較**（既定）
   - 同じ初期投資額、積立額、期間を各銘柄へ適用
   - 配当、総資産、トータルリターンを比較
2. **同じ目標配当で比較**
   - 同じ税引後月額目標を各銘柄へ適用
   - 現時点の必要投資額、必要口数、同じ積立額での達成時期を比較

個別に異なる投資額を入れる「自由比較」は後続機能とする。公平比較の意味が薄れ、結果の説明が難しくなるため、MVPの既定導線には入れない。

#### 比較表

| 分類 | 指標 | 意味 |
|---|---|---|
| 現在 | 初期利回り | 現在価格に対する税引前利回り |
| 現在 | 初年度税引後配当 | 初期収入の多さ |
| コスト | 経費率 | ETF内部の年次コスト |
| 将来収入 | 5年・10年・期末の税引後配当 | 収入成長 |
| 将来収入 | 累計現金受取額 | 実際に外へ取り出した配当 |
| 資産 | 期末評価額 | 保有資産の価値 |
| 資産 | 受取額込み総資産 | 配当と評価額の合計 |
| 収益 | 累積トータルリターン | 投資額に対する総損益 |
| 収益 | XIRR | 入出金時期を反映した年率収益 |
| 元本 | 元本維持率 | 評価額÷累計投資額 |
| 元本 | 1口価値維持率 | 期末価格÷初期価格 |
| 目標 | 目標達成時期 | 目標配当へ最初に届く時期 |
| 目標 | 期限内の必要積立額 | 同じ期限に届くための毎月積立額 |

#### 条件別ハイライト

2件以上の場合だけ表示する。

- 初年度の手取り配当が最大
- 10年後の手取り配当が最大
- 期末総資産が最大
- 経費率が最小
- 目標到達が最速
- 元本維持率が最大

同率は複数表示する。総合スコアや「おすすめ」はMVPで出さない。

#### 比較の差分説明

2件以上の場合だけ表示する。

表だけで終わらせず、機械的に生成できる短い説明を最大5件表示する。

表示例:

- Aは初年度の手取りがBより8,400円多い
- Bは10年後の年間手取りがAを上回る
- Cは経費率が最も低い
- Aは目標へ最速で到達するが、期末の元本維持率は最も低い
- BとCの総資産差は2%未満で、入力仮定の小さな変更で順位が変わり得る

説明は結果の差を述べるだけにし、「〜なので買うべき」のような推奨文へ変換しない。

#### 比較の安定性表示

2件以上の場合だけ表示する。

入力どおりの結果だけで優位を断定しないため、単体画面と同じ固定ストレスを各銘柄へ適用する。

- 4ケース中、期末総資産が最大だった回数
- 4ケース中、期末税引後配当が最大だった回数
- ストレスケースで目標未達になるか

これを「優勝回数」ではなく「条件変化への安定性」と表示する。モンテカルロ確率とは扱わない。

#### 比較の公平性

- 既定は各銘柄へ同じ初期投資額・積立額を投入する
- 端数口数ありの共通条件で比較する
- すべての入力と表示をJPYへ統一する
- 各銘柄の税・コストは個別に適用する
- XIRRの外部キャッシュフロー定義を全銘柄で統一する

## 7. 計算仕様

公開MVPの画面はJPY固定とする。既存エンジンの通貨・為替・売買コスト・端数可否・期末売却・開始日・配当イベントの型は回帰互換のため残すが、画面からは`currency = "JPY"`、`FX = 1`、`annualFxChange = 0`、`fxSpread = 0`、売買手数料0、端数口数あり、期末売却なし、固定内部基準日、配当イベントなしを渡す。これらは公開MVPの入力項目ではない。

### 7.1 記号

| 記号 | 意味 |
|---|---|
| `t` | 開始からの月番号、0〜T-1 |
| `P_t` | 月初の1口価格、現地通貨 |
| `D_y` | y年目の1口年間配当、現地通貨 |
| `Q_t` | 保有口数 |
| `FX_t` | 現地通貨1単位あたりJPY |
| `C_t` | 未投資JPY現金 |
| `F_t` | 未投資現地通貨現金 |
| `B_t` | 当月積立額、JPY |
| `w_m` | 月次概算比率。公開MVPでは常に1/12 |

### 7.2 初期配当

年間1口配当が入力された場合:

```text
D_0 = annualDividendPerShare
initialYield = D_0 / P_0
```

利回りが入力された場合:

```text
D_0 = P_0 × initialYield
```

内部計算の正本は1口年間配当とし、利回りは派生値にする。

### 7.3 配当変化

公開MVPの継続的な年間配当変化:

```text
D_y = D_0 × (1 + annualDividendChangeRate) ^ y
```

正数なら継続的な増配、負数なら継続的な減配となる。ランダムなボラティリティやモンテカルロはMVPに含めず、感応度分析の固定4ケースで変動幅を確認する。内部の2段階成長・配当イベント型は回帰互換のため残すが、公開画面からは使わない。

### 7.4 価格と経費率

公開画面では将来の価格変化率を入力させず、値動きを0%に固定する。経費率だけを価格へ反映する。

```text
monthlyPriceFactor
  = (1 + 0) ^ (1 / 12) × (1 - expenseRatio) ^ (1 / 12)
```

```text
P_(t+1) = max(0, P_t × monthlyPriceFactor)
```

内部の価格成長率と入力基準の型は計算エンジンの回帰互換のため残すが、公開画面からは`annualPriceGrowthRate = 0`、`returnBasis = "grossBeforeExpense"`を渡す。

### 7.5 為替（内部互換）

```text
FX_t = FX_0 × (1 + annualFxChange) ^ (t / 12)
buyFx_t = FX_t × (1 + fxSpread)
sellFx_t = FX_t × (1 - fxSpread)
```

公開MVPでは`FX_t`を常に1、スプレッドを0とし、為替入力欄は表示しない。

### 7.6 購入口数と購入コスト

当月の購入原資:

```text
availableJpy = previousUnusedJpy + monthlyContribution
```

固定手数料を払っても購入可能な場合、概算購入可能元本:

```text
maxAssetNotionalJpy
  = max(0, (availableJpy - fixedBuyFeeJpy) / (1 + buyFeeRate))
```

現地通貨建ての購入可能元本:

```text
maxAssetNotionalNative = maxAssetNotionalJpy / buyFx_t
rawUnits = maxAssetNotionalNative / P_t
units = fractionalAllowed ? rawUnits : floor(rawUnits)
```

実コスト:

```text
assetNotionalJpy = units × P_t × buyFx_t
buyFeeJpy = units > 0
  ? fixedBuyFeeJpy + assetNotionalJpy × buyFeeRate
  : 0
totalPurchaseCashJpy = assetNotionalJpy + buyFeeJpy
unusedJpy = availableJpy - totalPurchaseCashJpy
```

積立額より固定手数料が大きい場合は購入せず、現金を翌月へ繰り越す。

### 7.7 分配・配当

月次概算の税引前配当:

```text
grossDividendNative_t = Q_t × D_y × w_m
```

公開MVPでは年間配当を12等分する。実際の支払月は再現せず、画面では「月平均」と表示する。既存エンジンの任意スケジュール型は回帰互換のため残す。

### 7.8 税金

```text
foreignTax = grossDividend × foreignTaxRate
domesticTaxBase = domesticTaxBaseMode == "afterForeignTax"
  ? grossDividend - foreignTax
  : grossDividend
domesticTax = domesticTaxBase × domesticTaxRate
foreignTaxCredit = foreignTax × foreignTaxCreditRate
netDividend = max(0, grossDividend - foreignTax - domesticTax + foreignTaxCredit)
```

NISAプリセットは国内税率と外国税回収見込率を0にするが、外国源泉税率は自動的に0にしない。

税計算は概算であり、証券会社の端数処理、外国税額控除の上限、控除時期、実際の申告を再現しない。税額の丸めは内部では行わず、表示時のみ行う。

### 7.9 再投資

```text
reinvestmentBudgetNative = netDividendNative × reinvestmentRate + unusedNativeCash
cashDividendNative = netDividendNative × (1 - reinvestmentRate)
```

同一通貨で再投資するため、再投資部分には為替スプレッドをかけない。購入手数料は適用する。

再投資購入の固定手数料がJPY建ての場合は、その月の基準為替`FX_t`で現地通貨へ換算する。配当だけでは手数料込みで1口も買えない場合、購入せず現地通貨現金へ繰り越す。

現金受取部分をJPY換算する場合:

```text
cashDividendJpy = cashDividendNative × sellFx_t
```

端数株不可で再投資しきれない現地通貨は`unusedNativeCash`へ繰り越す。

### 7.10 期末評価額

売却しない場合:

```text
marketValueJpy = Q_end × P_end × FX_end
endingWealth = marketValueJpy
             + unusedJpy
             + unusedNativeCash × FX_end
             + cumulativeCashDividendJpy
```

内部互換の期末売却を有効にした場合:

```text
grossSaleJpy = Q_end × P_end × sellFx_end
saleFeeJpy = fixedSaleFeeJpy + grossSaleJpy × saleFeeRate
liquidationValueJpy = max(0, grossSaleJpy - saleFeeJpy)
```

公開MVPでは期末売却を使わない。内部互換の期末売却では譲渡益課税を計算しない。

### 7.11 主要KPI

```text
cumulativeContribution = initialInvestment + sum(monthlyContributions)
totalWealth = endingMarketValue + cashBalances + cumulativeCashDividend
totalGain = totalWealth - cumulativeContribution
cumulativeTotalReturn = totalGain / cumulativeContribution
principalRetention = endingMarketValue / cumulativeContribution
unitValueRetention = endingPrice / initialPrice
```

再投資された配当は、評価額に含まれるため総資産へ重複加算しない。累計配当を表示する場合も、現金受取額と再投資額を分ける。

### 7.12 Yield on Cost

```text
forwardGrossAnnualDividend = Q_end × D_current × FX_end
yieldOnCost = forwardGrossAnnualDividend / cumulativeContribution
```

税引後版も別表示できる。ただし、取得時期の異なる口数を一つの取得価格で扱わず、累計投資額に対する参考指標と明記する。

### 7.13 目標必要投資額

単純逆算は現在条件で即時計算する。

税引後年額目標の場合:

```text
netTaxFactor
  = 1 - foreignTaxRate
    - domesticTaxRate × domesticTaxBaseFactor

domesticTaxBaseFactor
  = domesticTaxBaseMode == "afterForeignTax"
    ? (1 - foreignTaxRate)
    : 1
```

実装では税関数へ1単位の配当を渡し、戻り値を`netTaxFactor`として使う。税式を別の場所に複製しない。

```text
requiredInvestmentApprox
  = targetNetAnnualDividend / (initialYield × netTaxFactor)
```

公開MVPの共通条件で必要額は、次の条件を満たす最小投資額を二分探索する。

```text
forwardNetAnnualDividend(investment) >= targetNetAnnualDividend
```

- 下限0
- 上限は倍増探索で見つける
- 収束許容幅は1円または表示通貨最小単位
- 最大反復回数を設定
- 利回り0または税引後係数0なら計算不能

### 7.14 目標達成時期

各月末に、その時点の保有口数・配当単価・税率から次の12か月の想定税引後配当を算出する。

```text
forwardNetAnnualDividend_t
  = taxAndConvert(Q_t × D_current)
```

初めて目標以上になった月を初回達成月とする。実際の過去12か月受取額ではなく、フォワード年額であることを表示する。

### 7.15 期限から必要積立額を逆算

達成希望月が指定された場合、毎月積立額を二分探索し、希望月末のフォワード税引後年額が目標以上になる最小積立額を求める。

```text
forwardNetAnnualDividendAtDeadline(monthlyContribution)
  >= targetNetAnnualDividend
```

- 下限0円
- 上限は倍増探索で見つける
- 1円または画面の表示単位内で最小となるまで収束
- 初期投資だけで達成する場合は0円
- 現実的な探索上限を超える場合は算出不可

### 7.16 XIRR

積立がある比較では単純リターンだけでは時期を反映できないため、資金加重収益率を表示する。

外部キャッシュフロー:

- 初期投資・毎月積立: 負
- 現金として受け取った税引後配当: 正
- 再投資配当: 内部移動なので含めない
- 期末評価額と未投資現金: 最終日に正

```text
NPV(r) = Σ CF_i / (1 + r) ^ (days_i / 365)
```

`NPV(r)=0`となるrを数値的に求める。解が存在しない場合は「算出不可」とし、無理に0%を返さない。

## 8. 月次計算順序

月次処理の順序を固定し、仕様とテストで共有する。

1. 年間配当変化率を適用
2. 月初積立額をJPY現金へ追加
3. JPYで購入し口数を追加
4. 年間配当の1/12を月次概算として計算
5. 外国税、国内税を控除
6. 指定率を同じ銘柄へ再投資
7. 非再投資分を現金受取へ加算
8. 月末の価格成長を適用
9. 翌月状態へ更新
10. 月末スナップショットとフォワード配当を記録

近似上、月初購入分は同月の配当対象になる。より正確な権利落ち日・権利確定日は自動取得フェーズで扱う。MVPの画面にこの近似を明記する。

現在の作業用キーと名前付き保存一覧用キーを分ける。名前は前後の空白を除いた1〜40文字とし、同じ名前で保存した場合は既存項目を上書きしてIDを維持する。一覧は更新日時の新しい順に表示する。復元時は単一・目標・比較の入力と選択中モードを置き換え、現在の作業用キーも更新する。削除は名前付き一覧だけを対象とし、現在開いている作業は変更しない。

計算結果は保存せず、入力から再計算する。これにより計算ロジック更新後の不整合を減らす。

JSONバックアップは名前付き保存一覧だけを対象とする。現在編集中の試算は、先に名前付き保存した場合に含まれる。書き出し時は形式識別子、スキーマバージョン、書き出し日時を付ける。読み込み時は全項目を検証し、不正な形式・未対応バージョン・不正な入力が1件でもあれば一覧を変更しない。既存一覧へ追加し、同名は既存IDを維持して上書きする。IDが別項目と衝突する場合は端末内で重複しないIDへ変換する。読み込み後も現在開いている試算は変更しない。

フェーズ5Bまで端末内保存だけを扱い、通信、外部アカウント、クラウド同期、URL共有は実装しない。

```text
src/domain/dividend-simulator/

├─ validation.ts
├─ tax.ts
├─ costs.ts
├─ growth.ts
├─ purchase.ts
├─ simulate.ts
├─ target.ts
├─ xirr.ts

```

責務:

- `tax.ts`: 税引前から税引後への変換のみ
- `costs.ts`: 売買・為替コスト
- `growth.ts`: 配当、価格、為替パス
- `purchase.ts`: 端数可否と手数料を含む購入
- `simulate.ts`: 月次状態遷移
- `target.ts`: 必要額二分探索と達成月
- `xirr.ts`: 資金加重収益率
- `aggregate.ts`: 月次から年次・KPIへ集約
- `compare.ts`: 同じエンジン結果を1〜3件並べるだけ

UIコンポーネントから式を直接書かない。

## 11. 表示仕様

### 11.1 用語

| 内部概念 | 画面表示 |
|---|---|
| gross dividend | 税引前の分配金・配当金 |
| net dividend | 税引後の分配金・配当金 |
| forward annual dividend | 現在条件での今後1年の想定手取り |
| market value | 評価額 |
| total wealth | 受取額込み総資産 |
| principal retention | 元本維持率（評価額ベース） |
| cumulative total return | 累積トータルリターン |
| XIRR | 入出金時期を考慮した年率収益 |

ETFでは「分配金」、株では「配当金」を優先表示する。共通画面では「分配金・配当金」とする。

### 11.2 注意表示

常時表示:

> この結果は入力した仮定に基づく概算であり、将来の成果を保証するものではありません。税額は口座、商品、居住地、申告状況などにより異なります。

条件付き警告:

- 経費率二重控除の可能性
- 価格成長率が大きくマイナス
- 配当成長率が長期に高すぎる
- 評価額が累計投資額を下回る
- 税引後係数が0以下
- 目標が期間内に未達
- 外国税額控除が概算である

### 11.3 数値表示

- JPY: 1円単位、主要KPIは万円・億円の補助表記可
- 比率: 原則小数2桁
- 口数: 端数口数ありで最大6桁
- 入力欄は生の数値を保持し、フォーカスを外した時に整形
- 0、未入力、計算不能を区別する

- 見出しは一つの目的だけを、短い日本語で示す
- 最初の見出しは機能名を直接示す「配当・分配シミュレーション」とする
- ラベルは利用者が入力・確認する内容を直接表し、内部実装の用語を避ける
- 補足文は入力方法、数値の意味、注意点のいずれか一つに絞る
- 「試算」「確認」「比較」「目標」「保存」の動詞を画面内で統一する

- スマートフォンでは軸の表示数を減らし、軸文字と選択点をPCより大きくする
- グラフ上でブラウザ標準のピンチズームを利用できる
- グラフ専用の拡大画面や横スクロールを追加しない
- 公開画面に年間価格変化率と価格変化率の基準を表示しない
- 将来の値動きは0%、経費率は控除前価格へ反映する前提を画面に明記する
- 単一銘柄、目標逆算、1〜3銘柄確認・比較、保存、JSONバックアップの既存操作を維持する

## 15. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 入力が多すぎる | 初心者が離脱 | 簡単設定と詳細設定を分離 |
| 現在利回りを将来固定 | 楽観的結果 | 配当変化と経費を反映して毎年再計算 |
| 経費率二重控除 | ETF結果が不正 | 公開画面は控除前価格・値動き0%へ固定し、専用テスト |
| 税の完全再現を期待 | 誤認 | 概算プリセット、上書き、注記 |
| 米国税・NISAの誤解 | 手取り誤差 | 外国税と国内税を分離 |
| 分配額だけで比較 | 高分配偏重 | 総資産、XIRR、元本維持を併記 |
| 「元本払戻し」の誤判定 | 信用・法務リスク | 観測可能な維持率のみ表示 |
| 成長率の過大入力 | 非現実的 | 範囲警告、シナリオ説明 |
| 端数・権利確定日の近似 | 実額との差 | MVP近似を表示、後で履歴対応 |
| 自動データ停止 | アプリ停止 | 計算を手入力・API非依存にする |
| 総合ランキング | 投資助言的な誤解 | 目的別ハイライトに限定 |
| 長期計算の浮動小数誤差 | 数値ずれ | 内部丸めを避け、許容誤差テスト |

## 16. 開発上の判断保留事項

実装開始前に、次だけ決めればよい。未確定でも計算エンジンは進められる。

1. フロントエンド構成（既存標準がなければReact + TypeScript候補）
2. チャートライブラリ
3. UIデザインのブランド名・色・ロゴ
計算仕様、比較軸、MVP境界はこれらに依存しない。

## 17. 推奨する初期サンプル

実在銘柄の古いデータを初期値にしない。説明用の架空3商品を用意する。

- 高分配型: 初期利回り高、増配低、経費率高
- 増配型: 初期利回り中、増配高、経費率低
- 低コスト安定型: 初期利回り低〜中、増配中、経費率最低

これにより、比較画面の価値を個別銘柄の推奨なしで示せる。
